AI in Production: Panellists Highlight Silent Failures, Harness Engineering, and Agent Governance

Olimpiu Pop · rss · 2026-10-16 source ↗ Reader 🖥️

Agentic systems in production fail silently (plausible-but-wrong output while every health check stays green) and ship code faster than humans can read it, so the panel argues that assurance must move out of manual review and static pre-release checks into automated CI gates, permanent production evals, and least-privilege agent identities, while the final go/no-go stays a business decision.

practical · expository — A reported panel discussion: it argues for action (automate review, make evals permanent, scope agents like new hires, keep the deploy decision with the business) by way of production failure anecdotes. Propositions are attributed to individual panellists rather than to the journalist.

Key terms

  • Semantic drift Silent Pipeline Drift (Semantic & Embedding Drift)
    Gradual flattening or mis-mapping of domain-specific meaning inside an LLM pipeline (e.g. 'member' treated identically in sales and customer-support domains by a text-to-SQL agent), yielding subtly wrong analytics that still pass standard tracing.
  • Embedding drift Silent Pipeline Drift (Semantic & Embedding Drift)
    A silent, unannounced update of the underlying embedding model shifts the vector-distance distribution, so fixed similarity thresholds start producing false positives and negatives in live traffic while infrastructure health checks remain green.
  • Silent failure
    A failure mode where the system returns convincing but wrong output and no conventional health signal (crash, error rate, latency) fires.
  • Evals as living infrastructure
    Evaluation treated as a permanent production system (span-level online tracing, LLM-categorised failure patterns, production edge cases fed back into offline benchmark suites) rather than a pre-release checklist.
  • Agent as new engineering hire
    A governance metaphor for limiting blast radius: give each agent its own non-human identity, tiered access (read-only vs reversible write), versioned third-party MCP dependencies, and secrets kept outside its runtime.
  • Shift left at the harness level
    Evaluate intent inside the agent harness before a pull request is generated, rather than inspecting the PR afterwards.

Arguments

Human code review must be demoted to the architecture/intent level and tactical checks automated. strength: medium
Explicit premises:
  • Coding agents generate production code faster than humans can review.
  • Line-by-line manual review cannot scale with agent velocity.
Implicit premises:
  • Tactical style and syntax defects are mechanically detectable and a negligible share of what review is for.
  • Mutation testing and CI gates give sufficient assurance on logic correctness once humans step back.
Inferences:
  • The scarce resource becomes the ability to specify intent and judge architecture, not to read diffs.
Evals must be treated as permanent production infrastructure. strength: high
Explicit premises:
  • Silent failures (semantic and embedding drift) leave all infrastructure health checks green.
  • Production edge cases are the best source of new benchmark cases.
Implicit premises:
  • Failure patterns can be reliably categorised by LLMs at scale (a judge-model trust assumption).
  • Ground truth for 'wrong but plausible' output is obtainable in production.
Inferences:
  • Quality assurance becomes an operations function with its own on-call and budget.
Agents should be governed through identity and access design, not through prompting. strength: medium
Explicit premises:
  • Prompt engineering is not a defence.
  • Agents can be induced to execute unauthorised actions (GitSpawn) and models can leak memorised secrets.
Implicit premises:
  • An agent's identity can be separated from its human principal's and stay stable across tool chains.
  • The human-hire analogy transfers: onboarding, tiered permissions and revocation are enough to bound autonomous behaviour.
Inferences:
  • Agent governance converges with IAM and secrets management, an existing discipline, rather than a wholly new one.

Narratives

  • Financial compliance agent blocking prohibited investment advice via vector-similarity thresholds; a silent embedding-model update shifted distance distributions and caused false-positive/negative spikes in live traffic with all health checks green.
    → Shows concretely that silent drift defeats infrastructure monitoring and motivates continuous, output-level evals.
  • Text-to-SQL agent treats 'member' identically across sales and customer-support domains, silently corrupting downstream analytics.
    → Illustrates semantic drift: errors that pass tracing but corrupt business decisions.
  • GitSpawn: malicious repository configuration executes unauthorised code during routine agent commands.
    → Supports the claim that agents need scoped capability, isolation and secrets outside the runtime.

Questions addressed

  • ✅ What breaks when agentic systems run in production?
    Silent semantic and embedding drift, data leakage through RAG and memorisation, review overload, and agent-config attack surfaces.
  • ✅ How can quality be assured when humans cannot read all agent-generated code?
    Automated CI checks, harness-level intent evaluation, mutation testing, living evals; humans keep architecture and intent.
  • ⭕ Who approves an agent for production, and on what basis?
    Asserted to be a business decision informed by engineering/security/privacy validation, but no criteria, thresholds or accountability mechanism are given.

Gaps

  • incompleteThe 'who approves it' question in the webinar title is answered with a single sentence (deployment approval is a strategic business decision) and no criteria, evidence standard, tiering or accountability mechanism; the business owner approving may also be the person least able to read the drift and eval evidence the panel says is needed.
    Read next: Read governance-by-principle and risk-tiering sources, and the 'agent-blame / moral-crumple-zone' accountability material, to see how approval authority and evidence standards are actually structured.
  • incompleteNo concrete detection mechanism for silent drift is described beyond 'span-level tracing and LLM categorisation of failures': how a team knows an embedding model was swapped, what canary/pinning practice stops it, and how ground truth for plausible-but-wrong output is obtained are all left open.
    Read next: Look for embedding/model version pinning, canary and shadow-comparison eval practice, and golden-set regression testing for RAG and text-to-SQL pipelines.
  • illogicalThe 'treat every agent like a new hire' analogy sits uneasily with evidence that anthropomorphic 'AI employee' framing lowers human accountability and error-catching; the panel uses the metaphor for access control only and does not address that risk.
    Read next: Compare with the AI-employee-vs-tool framing experiments and with delegated-authority-grants / bounded task grants as a non-anthropomorphic alternative.
  • incompleteMutation testing and CI gates are offered as replacements for line-by-line review, but there is no evidence that they catch the design and intent defects reviewers catch, and the news summary gives no data from the panel.
    Read next: Look for empirical studies of what agent-era review catches, and mutation-testing results on agent-written tests.
