Evolutionary architecture should be understood not as making change easy but as a continuous feedback system that keeps change safe, clear and deliberate, in which fitness functions detect drift, comprehension keeps people understanding what they change, boundaries define where independent change may happen, platforms make safe practice the default, and organizational design makes the boundaries survive in reality.

Key terms

  • Evolutionary architecture (as continuous feedback system)
    Architecture treated not as a diagram of today's system but as a set of mechanisms (fitness functions, comprehension checks, boundaries, platforms, org design) that let a system keep changing without losing coherence.
  • Agentic fitness function Agentic Fitness Functions
    A governed AI judgment layer inside CI/CD that evaluates semantic drift, boundary fidelity and architectural risk where deterministic rules cannot.
  • Comprehension as an architectural characteristic
    Human understanding of the system, which decays when AI commoditizes code output, treated as a first-class quality attribute with metrics and design checkpoints.
  • Cognitive debt Cognitive Debt
    The silent decay of system comprehension that accumulates as AI-generated code outpaces human understanding, threatening safe evolution.
  • Platform guardrails
    Platform-provided constraints and defaults that balance regional autonomy with centralized security, compliance and observability, without central lock-in.
  • Vibed prototype
    An AI-assisted prototype built quickly by 'vibing' that must be evolved into a distributed production system without a full rewrite.
  • Inverse Conway Maneuver
    Deliberately restructuring teams and lines of business so that ownership federates and the architecture follows, achieving deployment independence while preserving coherence.

Arguments

Evolutionary architecture is a continuous feedback system rather than a pattern catalog. strength: medium
Explicit premises:
  • Fitness functions signal when a system drifts.
  • Comprehension confirms people still grasp what they are modifying.
  • Boundaries define where independent change can happen.
  • Platforms turn safe practices into repeatable defaults.
  • Organizational design ensures boundaries survive contact with reality.
  • None of these concerns exist in isolation.
Implicit premises:
  • Each mechanism closes a feedback loop (sense, understand, contain, default, sustain) rather than prescribing a structure.
  • Six practitioner articles from one cohort are sufficient to generalize into a model of the discipline.
  • Safety and deliberateness of change are the binding constraints on evolvability, ahead of raw ease or speed.
Inferences:
  • A system missing any one mechanism (e.g. comprehension) can pass the others' checks and still evolve unsafely.
  • Fitness functions themselves need feedback: if agentic judges are used, someone must be able to understand and audit them, which couples the detection and comprehension mechanisms.
Human comprehension must be treated as an architectural characteristic. strength: medium
Explicit premises:
  • AI commoditizes code output.
  • System comprehension silently decays as output rises, creating cognitive debt.
  • A system that is not understood cannot evolve safely.
Implicit premises:
  • Understanding is a property that can be engineered and measured at the system level (socio-technical metrics, design checkpoints), not only a personal trait.
  • The rate of AI code generation will keep exceeding the rate of human comprehension.
Inferences:
  • Throughput metrics for AI-assisted delivery are incomplete without a comprehension counter-metric.
  • Agentic fitness functions that automate judgment could accelerate comprehension decay if humans stop reading the findings.

Narratives

  • A B2C platform expanded to serve B2B customers, requiring database schema evolution, backward-compatible API changes across team boundaries and refactored service boundaries.
    → Illustrates that fitness functions plus domain-aligned team boundaries keep a growing system maintainable.
  • A vibe-coded prototype grows into a distributed production system in three phases without being rewritten.
    → Supports the claim that AI-assisted prototypes can evolve in place if domain boundaries, golden paths and automated governance are introduced step by step.

Questions addressed

  • ✅ How can architecture keep a system changing safely when technology, organization and AI-generated code are all moving at once?
    Treat architecture as a continuous feedback system of drift detection, comprehension, boundaries, platform defaults and organizational design (at the level of framing; the detail is in the PDF).
  • ✅ How can autonomy (regional, team, line-of-business) coexist with central security, compliance and coherence?
    Platform guardrails, domain boundaries and the Inverse Conway Maneuver, per the abstracts.
  • ⭕ Who or what governs the governors: how are AI judges, platform defaults and comprehension metrics themselves kept honest?
    Not addressed in the visible text.
