Article: Agentic Fitness Functions: Extending Evolutionary Architecture Beyond Deterministic Rules

Hemant Kumar Mahato, Łukasz Sieczkowski, Vijayasenthilkumar Kuppusamy · rss · 2026-08-17 source ↗ Reader 🖥️

Deterministic fitness functions should remain the primary architectural governance mechanism, but calibrated, evidence-scoped, escalation-capable AI 'agentic fitness functions' should be added as an advisory judgment layer for architectural concerns that are evidence-bound but not reducible to a rule — boundary fidelity, semantic contract drift, stale ADR assumptions — so that architectural judgment itself becomes observable, auditable, and, where patterns repeat, convertible back into deterministic guardrails.

practical · mixed — Primarily practical/prescriptive (argues for a specific governance pattern teams should adopt), built expositorily (definitions, anatomy, a reference implementation) and argumentatively (defends the deterministic/agentic split against the objection that AI judgment is unreliable), with three worked examples functioning as narrative illustration.

Key terms

  • agentic fitness function Agentic Fitness Functions
    An architecture-governance check whose evaluator is a calibrated AI agent, whose criteria are an analytic rubric, and whose output is a structured verdict with evidence, confidence, and rationale — subordinate to and never a replacement for deterministic fitness functions.
  • evidence contract Agentic Fitness Functions
    The deliberately limited, named set of artifacts (PR diff, changed API spec, relevant ADRs, ownership metadata, service catalog entry, deterministic-check output, trace window) the agentic judge is allowed to inspect for a given verdict.
  • boundary fidelity
    Whether a change preserves the intended ownership boundary of a business capability — semantic coupling, hidden coordination paths, shared-state abstractions, leaked knowledge across bounded contexts — even when it violates no explicit dependency rule.
  • structured verdict Agentic Fitness Functions
    A machine-readable judgment output (score, confidence, violated_criteria, evidence references, recommended_action) as opposed to a conversational essay — required so the result can be stored, trended, and audited like any other governance signal.
  • rubric
    A versioned, named-criteria scoring instrument applied by the agentic judge, treated and reviewed like code (pull-request review, version numbers, re-run against the calibration set on any change).

Arguments

Agentic fitness functions are a defensible, disciplined extension of evolutionary architecture rather than an abandonment of the rigor deterministic fitness functions established. strength: medium
Explicit premises:
  • Deterministic fitness functions have a hard ceiling — they only protect what reduces to a rule, threshold, schema, or executable experiment.
  • Manual review is the historical fallback above that ceiling, but does not scale to modern change volume (every PR, every contract diff, every agent-generated patch).
  • A calibrated AI agent, given a scoped evidence pack and a versioned rubric, can return a structured, auditable verdict (score, confidence, rationale, evidence) rather than an unaccountable opinion.
  • The pattern keeps deterministic gates as gates and treats agentic checks strictly as advisory signals subject to human escalation.
Implicit premises:
  • A probabilistic AI verdict, properly scoped and calibrated, counts as legitimate governance evidence rather than merely a heuristic hint that a human could ignore without cost.
  • Organizations can reliably build and sustain the calibration sets, rubric-review process, and audit trail the pattern depends on — i.e., adopting this pattern does not simply relocate the same finite-reviewer-capacity bottleneck from code review onto rubric/calibration maintenance.
Inferences:
  • If rubric and calibration-set maintenance is itself a scarce, senior-reviewer-bound activity, the 'advisory signal via agent' pattern may not relieve the review bottleneck so much as move it upstream to a smaller number of higher-stakes reviews — a possibility the article never quantifies or addresses.
The known failure modes of LLM-as-judge systems (position, verbosity, self-enhancement bias, non-determinism, prompt injection, rubric drift) can be controlled without compromising the pattern's usefulness for architecture governance. strength: medium
Explicit premises:
  • A named failure-mode-to-control table maps each bias to a specific mitigation (dual-ordering evaluation, evidence-only scoring, separate judge model, repeated-run variance treated as low confidence, treating repo content as evidence not instruction, versioned/reviewed rubrics).
  • Confidence and evidence references are made explicit parts of every verdict rather than hidden.
Implicit premises:
  • The failure-mode taxonomy imported from general LLM-as-judge evaluation literature transfers cleanly to architecture-governance judging without domain-specific failure modes of its own.
Inferences:
  • Because fitness-function verdicts gate real production changes on a recurring basis (unlike a one-off eval run), even a purely 'advisory' false positive has an ongoing organizational cost — reviewer fatigue and alert fatigue — that the article's controls address for correctness but never discusses for volume or throughput.

Narratives

  • Three worked examples — a Boundary-Fidelity Reviewer that reasons about ADRs, ownership metadata, and package graphs; a Semantic Contract Evaluator that assesses whether a backward-compatible schema diff still preserves domain meaning; an ADR Drift Monitor that periodically checks whether an ADR's original assumptions (e.g., 'traffic is low enough for synchronous communication') still hold against current operational metrics.
    → Shows, rather than argues abstractly, what 'evidence-bound but judgment-heavy' architectural concerns look like in practice and how the anatomy (intent, evidence contract, judge, structured verdict) resolves each without blocking deployment.
  • A minimal structured-verdict JSON example: a 'checkout-boundary-fidelity' check scoring 0.68 with 0.74 confidence, flagging that a PaymentSession DTO leaking into a public OrderEvent violates semantic coupling per ADR-014, with a recommended action to move it behind a checkout-owned adapter.
    → Grounds the abstract 'anatomy' in a concrete, plausible artifact, implicitly supporting the claim that agentic verdicts can be as structured and reviewable as any deterministic tool's output.

Questions addressed

  • ✅ Can architectural governance be extended beyond what deterministic rules can check, without abandoning the rigor evolutionary architecture built around deterministic fitness functions?
    Yes, via a layered pattern: deterministic gates stay gates for objective invariants; a calibrated, evidence-scoped, versioned-rubric AI judge is added as an advisory signal for judgment-heavy concerns, with mandatory human escalation on low confidence or disagreement, and a promotion path back into deterministic rules once findings stabilize.
  • ✅ How do you keep an AI architectural judge auditable, calibratable, and resistant to the known failure modes of LLM-as-judge systems (bias, prompt injection, non-determinism)?
    Calibration against a labeled set of prior changes; versioned, code-reviewed rubrics; a named bias-to-control mapping; judge/generator model isolation; treating repository content strictly as evidence, never as instructions.
  • ⭕ What is the actual cost, at organizational scale, of maintaining calibration sets and rubric review across many fitness functions — and does that reproduce the same finite-reviewer-capacity bottleneck the pattern is meant to relieve?

Gaps

  • incompleteNo empirical evaluation of the pattern itself is reported — no precision/recall/false-positive numbers from an actual calibration run, no production case study, only a reference implementation and a hypothetical worked example. The article's confidence that calibration 'demonstrates acceptable precision, recall, and variance' is asserted as a process, never shown as an outcome.
    Read next: Look for a follow-up piece, or independent case study, reporting real calibration results (false-positive rate, override rate, time-to-escalation) for an agentic fitness function running against production PR traffic.
  • incompleteThe article never addresses who reviews and maintains the calibration set and rubric over time, across potentially many fitness functions (boundary fidelity, semantic contracts, ADR drift, and whatever else a team adds) — this could reproduce, at the rubric-review layer, exactly the finite-senior-reviewer-capacity bottleneck the pattern is proposed to relieve at the code-review layer. This corpus already flags a structurally identical concern about spec-authoring capacity in extract-context-store-evolutionary-architecture#g1.
    Read next: Look for treatments of AI-eval/rubric maintenance cost at scale — how many rubrics one architecture team can realistically own and keep current.
  • illogicalThe article treats judge disagreement as valuable signal of a real architectural trade-off that should always escalate to a human, but also recommends promoting recurring agentic findings into deterministic rules once the team 'agrees they represent real violations.' No criterion is given for distinguishing a finding that has become stable enough to deterministic-ize from one where persistent disagreement is itself the correct, ongoing state — the two prescriptions pull in opposite directions without a stated tiebreaker.
    Read next: Look for a worked example or decision procedure for when to stop escalating a recurring disagreement and instead write a rule.
  • uninformedThe article's optimism about a calibrated agentic judge reliably assessing boundary fidelity from ADRs, ownership metadata, and package graphs doesn't engage a directly relevant finding already in this corpus: extract-fowler-bockeler-static-sensors-iii found that even a strong model (Claude Opus 4.7) interpreting raw coupling metrics produced 'lackluster, often wrong' findings when it could not distinguish intentional patterns (DI factories, shared frontend/backend schemas) from genuine coupling smells — a near-identical judgment task to boundary-fidelity review.
    Read next: extract-fowler-bockeler-static-sensors-iii (same corpus) — read the specific failure modes an LLM shows when interpreting structural/coupling evidence without richer context.

Closes gaps elsewhere

  • Architecture as Code to Teach Humans and Agents About Architecture · g4 — The earlier essay left the tension between 'divergence is feedback, not failure' and 'constraints are inviolate for agents' unreconciled.
