How Claude Code Is Built

Gergely Orosz · pdf · 2025-09-23 source ↗ Reader 🖥️

Agent-Native DesignAgentic EngineeringClaude CodeMulti-Agent OrchestrationPull Requests & Async Code ReviewRisk TieringSRE & Incident ResponseTest-Driven Development
Claude Code is built by a small team that treats the Claude model itself — not its own surrounding code — as the real product, deliberately minimizing scaffolding, choosing an "on-distribution" tech stack the model already masters, deleting code whenever a new model release subsumes it, and restructuring code review, testing, incident response, and prototyping around AI doing the first pass; Orosz presents this as a plausible preview of how "AI-first" engineering teams will operate, while flagging that Anthropic's unlimited, cost-free access to its own frontier model and its identity as a research lab (not a product company) limit how directly the specifics transfer elsewhere.

practical · mixed — Primarily expository/narrative reporting (an interview-based case study of how one team builds a product), structured around seven numbered sections, but it closes with an explicitly argumentative claim: that this team's practices preview the future of AI-assisted engineering teams generally — a claim the author himself partially undercuts with caveats about Anthropic's atypical context.

Key terms

  • Product overhang
    Boris Cherny's term (attributed to AI-industry usage) for the gap between what a model is already capable of doing and what the product built around it is designed to let it do — i.e., the model has latent capability the product hasn't caught up to exposing.
  • On distribution / off distribution
    Whether a chosen technology (a language, framework, or stack) is something the model already has deep training exposure to and is good at using ("on distribution": TypeScript, React) versus something more exotic the model would need to be explicitly taught ("off distribution").
  • AI-first software engineering
    Not merely using AI tools alongside a normal process, but restructuring the process itself so AI does the first pass by default — on code review, security review, test-writing, incident triage, and monitoring-dashboard construction — with a human providing a second pass only where warranted.
  • Multi-clauding
    Running several separate Claude Code agent instances in parallel on different tasks at once, as a single engineer, rather than working on one task at a time.

Arguments

Claude Code should run locally with no virtualization/sandboxing and rely on a user-granted permission system as its safety mechanism. strength: medium
Explicit premises:
  • Simplicity is the team's default heuristic for every design decision
  • The simplest answers to 'where do you run shell commands' and 'where do you read/write files' are locally
  • A tiered permission system can intercept a dangerous action (e.g. deleting a file) before it happens, and lets users grant, grant-persistently, or reject
Implicit premises:
  • The marginal safety benefit of a VM/container sandbox is smaller than the complexity cost it would add to the product
  • Users will reliably notice and correctly respond to permission prompts, rather than habitually auto-approving them over time
  • A team-, project-, and company-tiered settings file (allow-listing commands like source-control check-ins) will not itself become a new, under-scrutinized source of silently over-broad permission
Inferences:
  • This design pattern externalizes safety responsibility from the architecture onto the end user's permission decisions, which only works as long as users remain an effective last line of defense
Claude Code's AI-first restructuring of code review, testing, incident response, and monitoring previews how general engineering teams will work in the near future. strength: low
Explicit premises:
  • Claude Code's own team has restructured code review, testing, oncall, and monitoring around AI doing first-pass work
  • Around 80% of Anthropic's technical staff use Claude Code daily ('obsessive dogfooding')
  • Other companies report similar wins (faster migrations, faster incident root-causing) using Claude Code
Implicit premises:
  • Anthropic's AI-first practices are not strongly conditioned on its atypical context (unlimited, cost-free model access; the LLM itself being the actual product)
  • What works for a roughly dozen-engineer team building a CLI tool generalizes to larger, more structurally diverse engineering organizations with different cost constraints, legacy systems, and compliance requirements
Inferences:
  • If other organizations' token-cost and quota constraints were relaxed, their review/testing/oncall processes would converge toward Anthropic's current practice

Narratives

  • Boris's walkthrough of building and testing 20 distinct UI prototypes for the todo-list feature over two days, with actual prompts shown for each iteration (hiding todos below tool calls, an interactive pill, a sliding drawer, moving the spinner), ending in the shipped Tab-toggle design.
    → Shows, rather than argues, that agentic prototyping collapses the cost of trying an idea to the point where mockups and formal design review become close to optional for fast UI decisions — directly supporting the proposition that 5-10 working prototypes per day is now achievable.
  • The subagents feature's three-day hackathon arc: day one sketches a complex, inter-agent-communicating topology; day two the team discards it as too complex for users to understand inside a simple terminal UI; day three they ship the simplest viable orchestrator.
    → Shows that even a team moving at agentic speed still exercises a deliberate, human engineering-judgment discipline of discarding complexity in favor of the simplest workable design — it is not simply 'let the agent build it,' but a classic design-review process compressed into three days.
  • Boris recounts glancing at a data scientist's screen and discovering they had figured out how to run Claude Code to write BigQuery queries and build visualizations, unprompted and unsupported by the Claude Code team.
    → Supports, through a single concrete anecdote, the broader claim that Claude Code's organic adoption now extends well beyond the software engineers it was originally named and built for.

Questions addressed

  • ✅ How do you make a locally-run AI agent with filesystem and shell access safe enough to use without constant hand-holding, without resorting to a sandboxed/virtualized architecture?
    A tiered, user-granted permission system (grant once / grant for future sessions / reject), backed by a multi-level settings file (project, user, company) that can allow-list already-approved commands via static analysis.
  • ⭕ How should an engineering team restructure code review, testing, and oncall once AI agents can reliably do first-pass work on all three?
    The article describes Anthropic's current answer (AI first pass, mandatory human second pass on review; AI-authored tests as the default; AI-assisted incident triage with human-in-the-driver's-seat) but does not resolve where this line should permanently sit as models keep improving, nor whether the human second pass stays meaningfully rigorous once a human has learned to trust the AI's first pass.
  • ⭕ Once a human reviewer knows an AI already gave a piece of code a first-pass review, will that human's second-pass review remain as rigorous as an unaided review, or will trust in the first pass quietly erode the second pass's diligence?
