Agile & XPNear-Zero-Cost CodeProxy Validity (Construct Validity of Measurement Proxies)
When Claude Code collapses the time to build software, the 2-week sprint (and the ceremonies and metrics built around it) stops fitting, but this doesn't mean Scrum has failed — because Scrum was always about empiricism (tight feedback loops of inspect-and-adapt), not about sprint length, so the right response is to compress the cycle to 2 days, drop effort-based metrics (story points, velocity), and replace them with a recurring value judgment ('should this ship?').

practical · mixed — A LinkedIn post reporting a concrete process change (2-week Scrum sprints replaced with a 2-day cycle) in response to AI-accelerated coding, framed around a general claim about what in Scrum survives that acceleration.

Key terms

  • Feature Gate
    A recurring decision point ('should this ship?') that replaces sprint review/retro as the team's governing checkpoint — a value judgment rather than a progress report.
  • empiricism (in Scrum)
    The inspect-and-adapt feedback loop that Scrum was designed to enable, independent of any specific cadence length.

Arguments

Teams whose build speed has been accelerated by AI coding agents should shorten their iteration cycle and replace effort-based tracking with a recurring ship/no-ship value judgment, rather than either keeping the old cadence or abandoning Scrum's discipline altogether. strength: medium
Explicit premises:
  • Claude Code has sped up implementation enough that 2-week-sprint ceremonies no longer fit the pace of work.
  • Scrum's actual value was always the empiricist feedback loop, not any particular cadence.
  • Effort-measuring metrics (story points, velocity) lose their point once effort itself is no longer the bottleneck.
Implicit premises:
  • A shorter cycle (2 days) is itself a form of inspect-and-adapt, just compressed, rather than a departure from Scrum's principles.
  • A 'should this ship?' judgment call is a sufficient replacement for effort-tracking as the team's governing control mechanism.
Inferences:
  • If build speed keeps increasing (further agentic acceleration), the appropriate cycle length should keep compressing further, with no principled floor other than the time needed to make a meaningful ship/no-ship judgment.

Questions addressed

  • ✅ Does AI-accelerated coding make Scrum/Agile obsolete?
    No — it makes Scrum's specific cadence (2-week sprints) and effort-based metrics obsolete, while making its empiricist core more relevant, not less.
  • ✅ What replaces effort-based tracking (story points, velocity) once AI does most of the implementation work?
    A recurring value judgment — a 'Feature Gate' asking 'should this ship?' — rather than any new quantitative proxy.
