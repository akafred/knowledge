Key terms

  • sports concierge agent
    A narrow, single-purpose, scheduled agent that filters a personal data feed (sports schedules) against stated preferences and delivers a curated weekly recommendation.
  • CONCIERGE.md / policy
    A single markdown file that defines the agent's job: goal, data sources, decision rules (including edge cases like finished tournaments and duplicate matchups), and expected output/delivery format. Used loosely — not a formal access-control policy, but a natural-language behavior specification.

Propositions

  • implicitA structured, context-rich preferences file (with a purpose-built editing interface) produces better agent decisions than working directly with the underlying raw JSON.conf: medium
  • explicitPre-fetching and combining schedule and preference data into one tool call, rather than letting the agent search for each game itself, reduces the work and error surface of the agent's task.conf: high
  • explicitWhen an agent's output misses the mark, the correct fix is to add detail to or adjust the natural-language policy file, not to change the underlying code or model.conf: high

  • implicitOrdinary OS-level tools (a Mac scheduler and a simple push-notification service) are sufficient for reliably running and delivering a personal agent's output on a recurring schedule — no dedicated agent-orchestration platform is needed.conf: medium

Arguments

The policy file (CONCIERGE.md) is the most leveraged place to iterate when a personal agent's behavior needs correcting. strength: medium
Explicit premises:
  • Chester's stated troubleshooting method, both generally and for the specific timezone bug, was to return to CONCIERGE.md and add or adjust instructions.
Implicit premises:
  • The agent's decision logic is fully governed by what's written in the policy file rather than by hidden code paths outside it.
  • The model reliably changes its behavior in the intended direction in response to more specific natural-language instructions.
Inferences:
  • This implies the policy file functions as the agent's real 'source code' for behavior — debugging the agent means editing prose, not code.

Narratives

  • A timezone bug: because the system defaulted to UTC, games could appear on the wrong day; Chester fixed it not by changing code but by adding explicit timezone instructions to CONCIERGE.md.
    → Shows concretely that even a narrow, well-scoped personal agent produces the classic class of silent default-assumption bugs — and that the piece's fix-the-policy-not-the-code proposition (p3) is more than a stated principle; it's what actually happened when something broke.

Questions addressed

  • ✅ How do you keep a personal agent from doing more than its assigned job?
    By scoping tool/file permissions narrowly to what the task requires, and by defining the agent's goal, data sources, and decision rules in one policy file.
  • ✅ How do you build a small, recurring personal AI agent without standing up dedicated agent infrastructure?
    Compose it from a policy file, a data-fetching script, Claude Code as the execution engine, OS-level scheduling (launchd), and a lightweight notification tool (ntfy).
