Just Talk To It - the no-bs Way of Agentic Engineering

Peter Steinberger · article · 2025-10-14 source ↗ Reader 🖥️

As coding-agent models (specifically GPT-5-Codex) get good enough to read a codebase and follow short, direct instructions on their own, most agentic-engineering 'harness ceremony' — subagents, RAG, elaborate plan files, custom hooks, MCP servers — becomes charade that works around older model limitations rather than exploiting current model capability, so the highest-leverage practice for a solo developer is to talk to the model directly and let judgment (about blast radius, context budget, and when real structure is needed) develop through intuition rather than process.

practical · mixed — A personal workflow check-in / field report (explicitly 'hand-written, not AI'): mostly argumentative advocacy for a minimal-ceremony agentic workflow, interleaved with narrative anecdotes and a tool-by-tool survey. It argues for a course of action (talk to the model directly; skip subagents, RAG, heavy plan files) more than it builds a general theory.

Key terms

  • blast radius Agent Security
    The anticipated scope of a change an agent is about to make — how many files it will touch and how long it will take — used as the sizing unit for deciding how many parallel agent tasks to run and whether a change can stay an isolated, atomic commit.
  • charade
    Harness ceremony (subagents, RAG, elaborate plan files, generic persona-prompting like 'you are an AI engineer') that looks like rigor but doesn't change model behavior — a label the author applies to anything he judges as working around a model limitation that no longer exists.
  • just talk to it
    The practice of giving the agent short, direct, conversational instructions (sometimes 1-2 sentences plus a screenshot) and trusting its own codebase-reading and judgment, instead of pre-engineering prompts, plans, or scaffolding.

Arguments

Developers should minimize harness ceremony — subagents, RAG, heavy plan files, elaborate custom hooks and personas, verbose AGENTS.md rules — and instead talk to the model directly, because model improvement is outpacing the value of most scaffolding built to compensate for older limitations. strength: medium
Explicit premises:
  • No hook stops a sufficiently determined model.
  • Manual terminal panes achieve what subagents promise, with more visibility and control.
  • GPT-5-Codex needs far shorter prompts and does more of its own file-reading than Claude required.
  • His own AGENTS.md has been shrinking as models absorb more world knowledge (the Tailwind-4 example).
Implicit premises:
  • Model improvement will keep outpacing the emergence of new failure modes that would require new scaffolding, rather than the two roughly offsetting.
  • A solo, highly experienced developer's intuition about when to add structure (a spec, a plan, 'take your time' trigger phrases) transfers to less experienced developers or to teams without the same accumulated judgment.
Inferences:
  • If 'harness features expire as models improve' generalizes, any team process built heavily around today's specific ceremony is itself a form of technical debt requiring deliberate pruning on each model generation — his own admission that his 800-line file is 'organizational scar tissue' he 'should clean up at some point' is this exact dynamic happening to him in real time, in tension with the post's 'just talk to it' simplicity claim.

Narratives

  • The 'blast radius' bomb metaphor: throwing many small bombs at the codebase (small, isolated changes, easy to reset) versus a few big 'Fat Man' bombs (large changes that resist isolated commits and easy rollback).
    → Illustrates and supports the proposition that task sizing, not tooling, is his primary mechanism for keeping multiple parallel agents safe and revertible.
  • The GitHub MCP server costing ~23,000 tokens of context (down from ~50,000 at launch) versus the `gh` CLI, which the model already knows how to use and which costs effectively nothing once its help text has been read once.
    → Makes concrete and supports the proposition that CLIs out-economize MCP servers on context budget for equivalent functionality.

Questions addressed

  • ✅ How can a solo developer run several coding agents concurrently without losing control of the codebase?
    A flat terminal-grid setup, task sizing by 'blast radius,' atomic per-agent commits, and the willingness to interrupt a running agent mid-task and ask for a status update.
  • ✅ Is heavy, upfront spec-driven development still the right default for agentic engineering?
    No, for his current workflow — iterative discuss-then-build is the default, with a written, cross-model-reviewed spec reserved only for genuinely tricky features.
  • ⭕ Does any of this (minimal ceremony, intuition over process, forgoing subagents and specs) translate to a team context — a shared codebase, code review across multiple people, onboarding someone without his accumulated intuition?
