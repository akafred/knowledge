Disposable Code Is Here to Stay, but Durable Code Is What Runs the World

Charity Majors · article · 2025-07-29 source ↗ Reader 🖥️

Coordination CostDisposable vs. Durable CodeFeedback LoopsTrust
Software development is splitting into two durably separate domains -- cheap, AI-generated disposable code and expensive, trust-earning durable code -- and because the cost of software is defined by its maintenance rather than its authorship, generative AI changes who can write code but does not eliminate the need for the fast-feedback-loop engineering discipline (tests, CI/CD, observability) that durable code has always required.

theoretical · argumentative — Primarily a conceptual reframe (software is bifurcating into two domains with different cost models) rather than a call to specific action, though it implies practical consequences (keep investing in tests/CI/observability, don't panic about durable engineering disappearing).

Key terms

  • Disposable code Disposable vs. Durable Code
    Code generated and used once or briefly with no intent to maintain it -- prototypes, scripts, experiments, hobby apps -- where low stakes make it acceptable to skip testing, review, and long-term understanding.
  • Durable code Disposable vs. Durable Code
    Code that runs critical, high-stakes systems (banking, medical, aviation, infrastructure) where failure is costly and unpredictable, requiring sustained investment in testability, observability, and incremental, trust-building rollout.
  • The 10x/9 rule (via Alex Ewerlof)
    For every additional '9' of reliability (SLO) you target, the system becomes roughly 10x more reliable but also roughly 10x more expensive to build and maintain -- used to argue reliability should be matched to actual need, not maximized.
  • Durable software is about trust
    Confidence in code is not a property that can be manufactured by test coverage alone; it accrues only from a track record of the code behaving correctly in production over time -- which is why durable code cannot be sped up the way disposable code generation has been.

Arguments

Generative AI does not eliminate the need for the durable-software engineering discipline (testing, CI/CD, observability, incremental rollout); it raises the stakes of skipping it. strength: high
Explicit premises:
  • The cost of software is defined by its maintainability, not its authorship.
  • Trust in code is earned only through production track record, which AI-generated code has not yet accumulated.
  • Only organizations already investing in reliability/observability are seeing AI efficiency gains.
Implicit premises:
  • Organizations and engineers are capable of distinguishing which code they're writing belongs to which domain (disposable vs. durable) and applying the right standard accordingly.
  • AI-generated code defaults to looking equally 'finished' regardless of which domain it was meant for, creating a risk that disposable-grade code gets mistaken for durable-grade code.
Inferences:
  • If engineers or managers cannot reliably tell which domain a given piece of AI-generated code belongs to, the article's reassurance ('don't freak out') may understate the actual organizational risk of durable systems silently absorbing disposable-grade code -- a risk the article doesn't directly address.

Narratives

  • The progression from 'generate some code to do a thing, do the thing, throw it away' (design mocks, data scripts, hobby apps) contrasted with code behind bank transactions, medical results, and nuclear power plants.
    → Makes the disposable/durable distinction concrete and visceral before the author argues for it abstractly via the maintenance-cost framing.
  • A new feature starting life as a disposable prototype, then being converted into durable code once its shape comes into focus.
    → Shows that the two domains are not fixed categories of code but a trajectory a given piece of code can travel along -- supporting the 'modalities, not separate codebases' proposition.

Questions addressed

  • ✅ Is writing code a valuable skill worth building, or an obsolete one on its way out (like cursive writing)?
    Both -- it depends entirely on which domain (disposable or durable) the code belongs to; durable code remains a profession, disposable code is becoming a general skill set.
  • ⭕ How will organizations and individual engineers reliably tell which domain a given piece of AI-generated code belongs to, especially as AI makes both kinds of code look equally polished on the surface?
