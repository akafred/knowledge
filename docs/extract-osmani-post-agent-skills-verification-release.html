Addy Osmani's 0.6.3 release of Agent Skills deepens the code-review skill specifically, on the premise that review -- not planning or generation -- is now the bottleneck limiting how much autonomy a coding agent can safely be granted, so the release invests in structural code-review depth (a 'reduce, don't relocate' lens, a Structural Remedies catalog, a file-size gate, severity-ranked findings) and adds a project-wide Definition of Done and an observability checklist, rather than expanding what agents are allowed to do unsupervised.

Thin, promotional release notes -- extraction kept proportionally short; its argumentative weight borrows from the author's other, more developed corpus pieces on the same project.

Key terms

  • Verification (as this release's theme) Verifiability (as the Quality Bar)
    The layer of review, testing, Definition-of-Done, and observability checks that gates whether agent-generated work is safe to ship -- named as the thing this specific release invests in, as distinct from generation or planning capability.
  • Structural Remedies catalog / 'reduce, don't relocate'
    A named taxonomy of code-review fixes that specifically flags moves which relocate complexity (e.g. extracting a function without reducing it) rather than genuinely reducing it, so such non-fixes aren't miscounted as improvements.

Arguments

This release's engineering investment should go toward the review skill, not toward expanding what agents are allowed to do autonomously. strength: low
Explicit premises:
  • Review is stated to be the bottleneck on agent autonomy.
Implicit premises:
  • Generation capability already exceeds what review can safely clear -- an assumption this post asserts but does not itself argue; the author's other corpus pieces (quality-in-the-harness, software-factories-light-dark) make this case at length.
  • Sharper, more structured review findings (severity, taxonomy, structural remedies) translate into agents producing more mergeable, lower-risk output, though no mechanism or evidence for this transfer is given here.
Inferences:
  • Investment ROI in agent tooling is higher on verification infrastructure than on generation speed, once a team has passed some threshold of agent adoption -- a claim this post assumes rather than demonstrates.

Questions addressed

  • ✅ Where should an agent-skills framework invest its next release, given that agents already skip spec/tests/review by default?
    In the review skill specifically -- deeper structural analysis, severity-ranked findings, and two new checklists (observability, Definition of Done).
  • ⭕ Do the new review-skill features (reduce-don't-relocate, file-size gate, severity labels) actually improve review outcomes -- fewer missed defects, less time to mergeable code?

Gaps

Popularity is not evidence the review skill actually works better.
