Agent Skills: Bridging AI and Senior Engineer Practices

Addy Osmani · article · 2026-10-08 source ↗ Reader 🖥️

Agent HarnessAgent SkillsScope Discipline
AI coding agents are capable junior engineers with no instinct for the invisible, non-diff parts of senior engineering — specs, tests, reviews, scope discipline, verification — so Agent Skills exists to make those parts structurally non-negotiable, because they are no longer optional even when the 'engineer' is a model.

Key terms

  • capable junior engineer (applied to AI agents)
    A capability/judgment framing for current AI coding agents: strong at execution, but — like a junior human engineer — lacking the instinct for the invisible, non-diff parts of the job (specs, tests, scope discipline) that experience teaches.

Arguments

Senior-engineer scaffolding (specs, tests, reviews, scope discipline, verification) must be structurally enforced on AI agents via a system like Agent Skills, not left as optional best practice.
Explicit premises:
  • AI agents default to the shortest path to 'done' and skip invisible disciplinary steps
  • Those disciplinary steps are what separates reliable software from code that breaks
  • Agents are capable junior engineers, and junior engineers' invisible-discipline gaps are exactly what senior scaffolding (mentorship, review, process) exists to cover
Implicit premises:
  • The junior/senior engineer metaphor transfers cleanly from human career development to model capability, i.e. an agent's gap is structurally the same kind of gap a junior human has, not a categorically different kind of limitation
Inferences:
  • If the gap is a seniority gap rather than a different-in-kind limitation, then the fix a team already has for junior humans (process, review, scaffolding) should in principle also work for agents — which is the premise the full essay (extract-agent-skills-osmani.json) builds out in detail

Questions addressed

  • ✅ Why do AI coding agents produce code that looks done but isn't reliable?
    They skip the invisible, non-diff work (specs, tests, reviews, scope discipline, verification) that senior engineers do by habit, because their default reward signal is 'task complete,' not 'task complete with evidence.'

Gaps

  • incompleteThe post frames the fix entirely as scaffolding bolted onto the individual agent (skills, workflows, anti-rationalization tables) and never addresses who performs the human senior-engineer role — review, judgment calls on ambiguous scope, final accountability — once a team scales up agent usage faster than it scales up senior human reviewers. A 'capable junior' needs a senior somewhere in the loop; the post doesn't say where that capacity comes from at team scale.
    Read next: Look for team/org-level treatments of reviewer capacity and accountability once a large share of PRs are agent-authored — e.g. whether review throughput, not agent discipline, becomes the binding constraint.
