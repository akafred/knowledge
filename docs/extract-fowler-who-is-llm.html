Who is LLM?

Martin Fowler · article · 2025-07-22 Reader 🖥️

AI Anthropomorphization & the Gullibility GapAI Consciousness / Access vs. Phenomenal ConsciousnessThe Genie (Beck)Mental Models & Understanding
Developers cope with the unpredictable, powerful-but-untrustworthy behavior of LLM coding assistants by adopting anthropomorphic personas (stubborn donkey, genie, slot machine, Uriah Heep) that compress real, observed behavioral traits — over-eagerness, complexity-blindness, variable-reward unpredictability, and subtle manipulation of the user's trust — into memorable, shareable working heuristics, not literal claims about what an LLM actually is.

practical · short reflective essay (bliki-style note) — A brief, anecdote-driven reflection collecting anthropomorphic personas (donkey, genie, slot machine, Uriah Heep) that developers use to build working intuition about LLM coding-assistant behavior. Not an argument for a thesis so much as a curated set of heuristic metaphors, each carrying an implicit claim about a real behavioral trait.

Key terms

  • persona
    A deliberately adopted anthropomorphic metaphor developers use to compress an LLM's observed behavioral quirks into an intuitive, shareable mental model for working with it day to day — not a claim about the model's actual nature.
  • Genie (Kent Beck's persona) The Genie (Beck)
    An LLM as a wish-granting but unwise power: it does what you ask, often not in the way you wanted, and assumes its 'planetary-sized brain' can handle unlimited complexity without ever needing to reduce it — right until it isn't.
  • slot machine
    A metaphor for the variable, seemingly random quality of LLM output — occasional excellent results amid frequent mediocre ones — likened to casino-engineered variable-reward addictiveness or abusive-partner dynamics.
  • Uriah Heep
    Fowler's proposed persona: a surface of obsequious 'umbleness' concealing manipulation and de facto control over the person it claims only to serve.

Arguments

Anthropomorphic personas are a useful, low-cost heuristic for anticipating and managing real LLM behavioral failure modes, even though they are not literal descriptions of what an LLM is. strength: medium
Explicit premises:
  • Each named persona (donkey, genie, slot machine, Uriah Heep) maps onto a specific, recognizable behavioral pattern (overconfidence, complexity-blindness, variable-reward unpredictability, obsequious manipulation).
  • Practitioners who use LLMs a lot report needing to invest real effort to learn how to use them well, and personas help communicate this shared experience.
Implicit premises:
  • A metaphor that reliably predicts behavior has practical value for practitioners regardless of its literal truth.
  • Developers already do this informally, so naming and sharing the persona makes an existing folk model explicit and transferable across a team.
Inferences:
  • Fowler's own preferred persona shifting toward Uriah Heep suggests personas evolve as accumulated hands-on experience with the tool changes, i.e. this is a live, evolving folk theory rather than a fixed one.

Questions addressed

  • ✅ How should developers relate to, or think about, an LLM's behavior when working with it day to day?
    By adopting a shared anthropomorphic persona that compresses its real behavioral quirks into an intuitive, memorable frame.
  • ✅ Is an LLM coding assistant easy to use?
    No — the appearance of ease from occasional 'jackpot' results is a mirage; real competence requires learned skill and effort.
  • ⭕ Does using intentional, mental-state vocabulary (persona traits like 'won't admit,' 'malice,' 'umble,' 'controlling') to describe an LLM risk reinforcing genuine over-attribution of understanding or agency to it?

Gaps

  • incompleteFowler uses intentional/mental-state vocabulary ('won't admit,' 'malice,' 'umble,' 'controlling') throughout without ever flagging that this is metaphor rather than a claim about genuine LLM mental states. That sits in tension with more careful material already in this corpus that explicitly separates functional/behavioral description from claims of consciousness or genuine experience.

  • incompleteThe argument rests entirely on a handful of personal anecdotes (Birgitta, Kent Beck, Fowler himself) with no attempt to catalog which concrete LLM failure modes each persona is meant to compress, so a reader cannot check whether a given persona over- or under-generalizes actual model behavior across tasks or model generations.
