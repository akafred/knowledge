Client-Side Event Sourcing

Achieving local-first software's goals by replaying an immutable log of events on the client, rather than syncing a mutable, auto-merging CRDT object — a structurally different but equally legitimate architecture, appropriate when an application's core need is an auditable history rather than freeform collaborative editing.

Also known as: event sourcing (client-side), immutable event log, replay events, three-tier web stack (moving away from)

Part of: Local-First Software

    Client-side event sourcing — replaying an immutable log of events rather than syncing a mutable, auto-merging CRDT object — is a structurally different but equally legitimate way to achieve local-first software's goals, and should be adopted (like local-first itself) only when an application's core value genuinely depends on offline resilience, client-side speed, and user data ownership, since restructuring where and how data lives is one of the most fundamental and hardest-to-reverse decisions a team can make.
