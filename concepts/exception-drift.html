Exception Drift (Operating Mode as Runtime State)

Temporary, authorized emergency/incident exceptions (altered routing, approvals, permissions) that outlive the incident that justified them because the platform has no authoritative, scoped, time-bound runtime representation of "which operating mode is active" — fixed by injecting organizational operating state (normal/incident/recovery, with scope/authority/expiry/status) into the agent runtime as a first-class input, alongside identity and permissions, so closure can be automatically verified.

Also known as: exception drift, operating mode, exception-aware agents, runtime operating state, incident mode as runtime input

Part of: Agent Governance (Internal)

Open gaps (1)

  • illogicalThe article insists memory should never decide whether an accommodation is 'still authorized' and that authoritative runtime state must win when the two disagree, yet allows expiry to be tied to a soft condition like 'incident-close' — a status that itself has to be recorded and read from somewhere, often by human judgment. If that status update is delayed, inferred, or manually entered, the 'authoritative state' is not obviously more reliable than the informal traces it's meant to replace; the piece never explains what structurally distinguishes a trustworthy 'incident-close' status from the kind of soft, human-mediated signal it dismisses when it comes from memory or prompts.
