Pipelines-as-Code vs. Declarative Config

The recurring trade-off between declarative/DSL pipeline or infrastructure configuration (inspectable, diffable, policy-governable) and defining the same logic in a general-purpose language (more expressive, less legible and harder to govern).

Also known as: pipelines as code, CI/CD as code, YAML vs code (pipelines), declarative vs imperative pipelines, workflow-as-code, code not YAML, general-purpose-language pipelines

  • Cloudflare Turns CI Pipelines into TypeScript Workflows Mark Silvester · 2026-08-17 source ↗ Reader 🖥️
    By modeling a CI/CD pipeline as a Cloudflare Workflow — where every stage is a checkpointed, independently-retryable step — @cloudflare/ci trades the inspectability and policy-governability of declarative YAML pipelines for a general-purpose language, a trade whose cost (deep binding to Workflows, Sandboxes, Containers, Durable Objects and R2) only pays off for teams already committed to Cloudflare, while the durable-step execution model and the human-gated self-healing pattern it demonstrates are the ideas worth taking even without the product.
