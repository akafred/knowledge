Distributed Caching & Invalidation

Architectural patterns for caching data across distributed/microservices systems — where caching lives (client library, sidecar, proxy, CDN edge), how it's invalidated (TTL, event-driven, write-through), and how it avoids stampedes and handles staleness during failures — trading strict freshness for load reduction and availability.

Also known as: entity cache, transparent proxy cache, proxy cache, cache stampede, thundering herd, single-flight, XFetch, dual TTL, event-driven invalidation, stale-while-revalidate

Documents (3)

  • Cloudflare Cuts 100 TB of Memory from 1.1.1.1 DNS Cache Leela Kumili · 2026-09-23 Reader 🖥️
    Cloudflare cut its DNS cache's per-entry memory footprint by 56% and freed ~100 TB of fleet-wide working-set memory, without sacrificing (and while improving) throughput and latency, by collapsing the in-memory representation of cache entries toward DNS wire format instead of a typed, allocation-heavy Rust structure.
  • Article: Implementing Chaos Engineering in Financial Payment Systems: Lessons from Enterprise ECS Deployments Salim Adedeji · 2026-09-08 source ↗ Reader 🖥️
    In regulated, stateful payment systems running on ECS, chaos engineering only works if teams first replace the standard stateless-web playbook's three violated assumptions — clean rollback, definable blast radius, and free production experimentation — with a compliance-integrated, four-stage blast-radius graduation, because it is measured behavior under actual injected faults, not configuration values or architecture review, that reveals where these systems actually break.
  • DoorDash Uses Envoy and Valkey for a 1.5M RPS Proxy Cache with 99.99999% Availability Leela Kumili · 2026-07-20 Reader 🖥️
    DoorDash's Entity Cache shows that moving caching out of individual services and into a transparent, infrastructure-layer proxy (Envoy + Valkey) — with event-driven invalidation, staleness-tolerant failure handling, and stampede-avoidance techniques — can absorb very large request volume at extremely high availability without requiring any application code changes.
