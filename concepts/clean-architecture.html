Clean Architecture (Ports & Adapters / Hexagonal Architecture)

An architectural style that isolates domain/application logic in a layer with zero infrastructure dependencies, enforced by module boundaries rather than convention, so business logic can be wired to different entry points (cloud providers, transports, frameworks) largely unchanged.

Also known as: hexagonal architecture, ports and adapters, onion architecture, domain/application/infrastructure layering, dependency rule (architecture), business logic isolation

Part of: Modularity & Coupling

  • Presentation: Clean Architecture for Serverless: Business Logic You Can Take Anywhere Elena van Engelen · 2026-07-27 source ↗ Reader 🖥️
    Structuring Function-as-a-Service applications with a simplified Clean Architecture — a domain and application layer with zero cloud dependencies, whose separation from infrastructure is enforced not by convention but by Gradle module boundaries, wired to cloud entry points via Spring Cloud Function's dependency injection — lets a team write business logic once and deploy it, materially unchanged, to multiple serverless cloud providers, eliminating vendor lock-in without giving up native cloud capabilities.
