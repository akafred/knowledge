Agent Harness Control Plane

The explicit contract a production agent harness must enforce so a non-deterministic model can't silently violate it — a single ordered commit path per mutable shared state, scoped and time-boxed approval objects rather than a vague memory of a click, bounded tool-call lifecycles, and a "receipt" that crosses the user-visible edge as proof of outcome, more trustworthy than a transcript or a tool's own self-reported success — turning standard distributed-systems discipline into boundaries an agent can't quietly cross.

Also known as: control plane, state ownership, mutation ordering, approval boundary, receipt vs. transcript, scoped approval object, tool call lifecycle

    The reliability of a production AI agent depends not on the model but on its harness — whether every fact an agent depends on has a single owner and replay path, concurrent state mutations are serialized through one ordered commit path, every unit of work has a bounded lifecycle, every approval is a scoped and expiring authority object rather than a remembered click, and every action is proven with a receipt that crosses the user-visible edge — because a model can only propose an action, and it is the harness, not the model, that commits it and proves it happened.
