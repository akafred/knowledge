Local-First Software

Software designed so the primary copy of a user's data lives on their own device — synced via open standard protocols and CRDT libraries such as Automerge — giving offline access, speed, resilience against provider shutdown, and genuine user ownership and portability; the principle Kleppmann applies across collaboration software (local-first) and decentralised social media (AT Protocol/BlueSky) to reduce vendor lock-in.

Also known as: local-first, local-first software, local-first movement, offline-first, primary copy on device, data agency, data portability, CRDT, CRDTs, Automerge, AT Protocol, atproto, Personal Data Server, open sync protocol

  • Podcast: Rethinking Data: Moving From the Traditional Three-Tier Web Stack to Client-Side Event Sourcing Johannes Schickling · 2026-07-27 source ↗ Reader 🖥️
    Client-side event sourcing — replaying an immutable log of events rather than syncing a mutable, auto-merging CRDT object — is a structurally different but equally legitimate way to achieve local-first software's goals, and should be adopted (like local-first itself) only when an application's core value genuinely depends on offline resilience, client-side speed, and user data ownership, since restructuring where and how data lives is one of the most fundamental and hardest-to-reverse decisions a team can make.
  • How to Build More Resilient Local-First Applications With AT Protocol Infrastructure Olimpiu Pop · 2026-07-13 source ↗ Reader 🖥️
    AT Protocol's personal-data-server-plus-relay infrastructure can serve as a general-purpose, resilient foundation for local-first distributed applications of any kind, not only social networking, by letting apps offload storage, sync, and auth to shared, fungible infrastructure instead of fragile app-specific backend servers.
  • Podcast: Increasing Users' Data Agency: From BlueSky's AT Protocol to the Local-First Software Movement Martin Kleppmann · 2026-07-06 source ↗ Reader 🖥️
    Users gain real agency over their data not by eliminating servers or fully decentralizing but by adopting open, standard protocols that keep data portable and provider-independent — the common principle Kleppmann traces from the unbundling of monolithic databases into modular building blocks, through BlueSky's AT Protocol, to the local-first software movement.
